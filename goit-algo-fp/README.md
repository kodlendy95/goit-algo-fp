# Фінальний проєкт GoIT: Основні алгоритми та структури даних

Репозиторій `goit-algo-fp` містить виконання **всіх семи завдань** фінального проєкту. Рішення написані на Python 3.10+; для графічних завдань використовуються `matplotlib`, `networkx` та `pillow`.

## Структура проєкту

```text
goit-algo-fp/
├── task1_linked_list.py           # Однозв'язний список
├── task2_pythagoras_tree.py       # Рекурсивний фрактал
├── task3_dijkstra.py             # Найкоротші шляхи
├── task4_heap_visualization.py   # Візуалізація бінарної купи
├── task5_tree_traversal.py       # DFS і BFS, анімації кроків
├── task6_food_optimization.py    # Жадібний алгоритм і ДП
├── task7_monte_carlo.py          # Два кубики: Монте-Карло
├── tree_utils.py                 # Спільні вузли й візуалізація
├── tests/
│   └── test_tasks.py             # Автоматичні тести
├── results/                       # PNG та GIF результатів
├── requirements.txt
└── README.md
```

## Як запустити

У терміналі в папці проєкту:

```bash
python -m pip install -r requirements.txt
```

Виконання завдань окремо:

```bash
python task1_linked_list.py
python task2_pythagoras_tree.py --depth 9
python task3_dijkstra.py
python task4_heap_visualization.py
python task5_tree_traversal.py
python task6_food_optimization.py
python task7_monte_carlo.py --throws 200000 --seed 42
```

**Завдання 2:** параметр `--depth` задає рівень рекурсії від 0 до 12. Якщо параметр пропущено, програма **запитує рівень у користувача** через `input()`. Параметр `--save` зберігає PNG, `--no-show` вимикає графічне вікно.

**Завдання 5:** параметр `--animate` генерує **покрокові GIF** для DFS та BFS. Для збереження зображень:

```bash
python task2_pythagoras_tree.py --depth 9 --save results/task2_pythagoras_tree.png --no-show
python task4_heap_visualization.py --save results/task4_heap.png --no-show
python task5_tree_traversal.py --save-dir results --animate --no-show
python task7_monte_carlo.py --throws 200000 --seed 42 --save results/task7_monte_carlo.png --no-show
```

Запуск автоматичних тестів:

```bash
python -m unittest discover -s tests -v
```

## Завдання 1. Однозв'язний список

У `task1_linked_list.py` створені класи `Node` та `LinkedList`.

- `LinkedList.reverse()` перенаправляє посилання `next` між вузлами, не створюючи новий список; складність **O(n)** за часом і **O(1)** за додатковою пам'яттю.
- `LinkedList.insertion_sort()` сортує вставками, переставляючи **вузли**, а не їхні значення; час **O(n²)**, додаткова пам'ять **O(1)**.
- `merge_sorted_lists(first, second)` об'єднує **два вже відсортовані** списки у відсортований результат за **O(n+m)**. Функція створює нові вузли, тому початкові списки залишаються незмінними.

Приклад:

```text
Початковий список: [4, 2, 7, 1, 5, 3]
Після реверсування: [3, 5, 1, 7, 2, 4]
Після сортування: [1, 2, 3, 4, 5, 7]
Результат об’єднання: [0, 1, 2, 2, 3, 4, 5, 6, 7, 8]
```

## Завдання 2. Дерево Піфагора

У `task2_pythagoras_tree.py` побудовано **геометричне дерево Піфагора** — фрактал із квадратів. Кожен квадрат рекурсивно породжує два менші, повернуті на 45°. Довжина сторони кожного дочірнього квадрата становить `1/sqrt(2)` від сторони батьківського. Коли рівень дорівнює нулю, рекурсія зупиняється.

За глибини `d` створюється `2^(d+1) - 1` квадратів; отже, кількість об'єктів зростає експоненційно. Рівень обмежений 12, щоб уникнути надмірного навантаження під час візуалізації.

## Завдання 3. Алгоритм Дейкстри

У `task3_dijkstra.py` зважений орієнтований граф представлено словником суміжності. Функція `dijkstra(graph, start)` використовує `heapq` — **бінарну мін-купу** — для вибору вершини з найменшою поточною відстанню. Функція `reconstruct_path()` відновлює маршрут за попередниками.

Складність із купою: **O((V+E) log V)** за звичайної оцінки для списків суміжності (або O((V+E) log(V+E)) для реалізації з дублюванням записів у `heapq`). Алгоритм підтримує лише **невід'ємні ваги**. Недосяжні вершини мають відстань `inf`.

Приклад від вершини A:

| Вершина | Відстань | Найкоротший шлях |
| --- | ---: | --- |
| A | 0 | A |
| B | 3 | A → C → B |
| C | 2 | A → C |
| D | 8 | A → C → B → D |
| E | 10 | A → C → B → D → E |
| F | 13 | A → C → B → D → E → F |
| G | ∞ | Недосяжна |

## Завдання 4. Візуалізація купи

У `task4_heap_visualization.py` довільний масив перетворюється на коректну бінарну **мін-купу** через `heapq.heapify`. Функція `heap_to_tree(heap)` створює дерево із вузлів, використовуючи індекси масиву:

- лівий нащадок вузла `i`: `2*i+1`;
- правий нащадок вузла `i`: `2*i+2`.

`tree_utils.py` використовує `Node`, `networkx` та `matplotlib` для відображення вузлів. У мін-купі значення батька не перевищує значень його дітей. Побудова мін-купи з масиву через `heapify` — **O(n)**, побудова дерева вузлів — **O(n)**.

![Бінарна мін-купа](results/task4_heap.png)

## Завдання 5. DFS і BFS: стек та черга

У `task5_tree_traversal.py` обхід у глибину (DFS, **preorder**) використовує **стек** (`list.append` / `list.pop`), а обхід у ширину (BFS) — **чергу** (`collections.deque`). **Рекурсія не використовується.** Складність кожного обходу — **O(n)**.

Відвідані вузли зафарбовуються індивідуальними шістнадцятковими RGB-кольорами (`#RRGGBB`) від **темно-синього до світло-блакитного**. У GIF анімації спочатку всі вузли сірі, потім з кожним кроком зафарбовується наступний вузол.

- **DFS (стек):** `0, 4, 5, 10, 1, 3`.
- **BFS (черга):** `0, 4, 1, 5, 10, 3`.

## Завдання 6. Вибір страв за бюджетом

У `task6_food_optimization.py` всі страви можна придбати **не більше одного разу** (задача 0/1 knapsack).

- `greedy_algorithm(items, budget)` сортує страви за відношенням `calories/cost`, а потім додає страви, що поміщаються в бюджет. Це швидка **евристика**, а не гарантія оптимальності. Складність **O(n log n)**.
- `dynamic_programming(items, budget)` будує таблицю `dp[i][b]`, де зберігається максимальна калорійність для перших `i` страв і бюджету `b`, та відновлює вибрані страви. Складність **O(n × budget)** за часом і пам'яттю.

За **бюджету 100** результати такі:

| Метод | Страви | Вартість | Калорії |
| --- | --- | ---: | ---: |
| Жадібний | cola, potato, pepsi, hot-dog | 80 | 870 |
| Динамічне програмування | pizza, pepsi, cola, potato | 100 | **970** |

**Висновок:** жадібний підхід не завжди забезпечує найбільшу сумарну калорійність; динамічне програмування знаходить оптимальний набір у межах бюджету. Коректність ДП додатково перевірено повним перебором усіх комбінацій у тестах.

## Завдання 7. Монте-Карло: кидання двох кубиків

У `task7_monte_carlo.py` симулюються `200 000` незалежних кидків **двох шестигранних кубиків**, кожен зі значеннями від 1 до 6. Для кожного кидка обчислюється сума, а ймовірність оцінюється як частота суми, поділена на кількість кидків.

Точна ймовірність для суми `s` обчислюється за формулою:

`P(S=s) = (6 - abs(7-s)) / 36`, де `s` від 2 до 12.

Порівняння за **200 000 кидків, seed=42**:

| Сума | Монте-Карло | Аналітична | Абсолютна різниця, в.п. |
| ---: | ---: | ---: | ---: |
| 2 | 2.792% | 2.778% | 0.015 |
| 3 | 5.543% | 5.556% | 0.013 |
| 4 | 8.348% | 8.333% | 0.014 |
| 5 | 11.118% | 11.111% | 0.007 |
| 6 | 13.911% | 13.889% | 0.022 |
| 7 | 16.500% | 16.667% | 0.167 |
| 8 | 13.939% | 13.889% | 0.050 |
| 9 | 11.172% | 11.111% | 0.061 |
| 10 | 8.277% | 8.333% | 0.057 |
| 11 | 5.616% | 5.556% | 0.060 |
| 12 | 2.785% | 2.778% | 0.007 |

![Порівняння частот і теорії](results/task7_monte_carlo.png)

### Висновки з аналізу методу Монте-Карло

1. **Результати симуляції узгоджуються з аналітичними ймовірностями.** Для всіх одинадцяти сум абсолютна різниця між частотою та теорією є малою. Найбільше відхилення за наведеного запуску — **0.167 відсоткового пункту** (сума 7).
2. **Сума 7 — найімовірніша** (теоретично 6/36 ≈ 16.67%), оскільки її дають шість різних упорядкованих пар значень кубиків. Найменш імовірні суми — 2 та 12 (по 1/36 ≈ 2.78%).
3. **Частоти не зобов'язані точно збігатися з теорією** через випадкові коливання у скінченній вибірці. Зі збільшенням числа кидків симульовані частоти зазвичай наближаються до теоретичних значень згідно із законом великих чисел.
4. **Перевірка правильності:** сума теоретичних і емпіричних імовірностей дорівнює 1 (з урахуванням похибки чисел з плаваючою крапкою), а всі отримані частоти мають правильний характер розподілу. Таким чином, реалізація Монте-Карло є коректною.
